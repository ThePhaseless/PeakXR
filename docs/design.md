# PeakXR design

PeakXR is a VR mod for PEAK 3.0 and 3.0.1, and still runs on 2.6.b (Unity 6000.3, Mono, URP, Photon PUN 2). It is a BepInEx 5 plugin plus a preloader patcher, MIT licensed and written clean-room: no code from PeakVR (Andrey04o), PEAK_VR, LCVR, CWVR or RepoXR. Research notes live in `docs/research/`.

## Goals

- Full VR play: head-tracked camera, tracked hands that are the character's own arms, controller locomotion.
- VR-native UI: menus and HUD are world-space panels in the 3D scene, never a flat screen floating in a void. The title menu stands you on the beach; loading keeps head tracking alive in a 3D space.
- Comfort first: snap or smooth turn, comfort vignette, no camera shake, no forced camera motion, fades instead of cuts, seated mode and height calibration.
- Physical interaction: grab items with your hand, eat by bringing food to your mouth, throw with your arm, climb by grabbing walls (each with a button-based fallback).
- Multiplayer with vanilla clients. Vanilla peers see head direction and basic reaching. Modded peers, VR or flat, see full head, hands and fingers.
- Survive game updates: see the rules below.

## Forward-compatibility rules

1. Harmony prefix/postfix only, no transpilers.
2. Every patch belongs to a `Feature` (`src/PeakXR/Framework`). A feature that can't find a target is rolled back alone, logged in the `[compat]` report at startup, and shown in the VR settings tab. The game keeps running.
3. Resolve non-public members with `GameMember` inside `Feature.Install`, never in static initializers.
4. Find objects by component type or by a reference the game already holds (`MainCamera.instance`, `Character.localCharacter`, `GUIManager.instance`). Never use hierarchy paths or scene indices. Scene names are allowed only as soft hints.
5. Never change `Application.version`, `CharacterSyncData` layout or RPC signatures, and never add RPC names that vanilla doesn't have.
6. No game-version lock. Log the game and Unity versions at startup.
7. After a game update, run `mise run decompile` (the old decompile stays in `decomp.prev/`), `mise run build` (catches direct API breaks such as a setter gone private) and `mise run compat-check` (every patch target, name lookup, injected `___field` and RPC name against the new decompile; with the baseline it also lists changed signatures and patched method bodies to re-read), then launch the game with `-peakxr-novr -peakxr-compat`: every feature installs without starting XR, and the `[compat]` lines in `BepInEx/LogOutput.log` show which ones lost a patch target.

## Runtime architecture

```
Preloader (BepInEx patcher)        Plugin (BepInEx plugin)
  picks runtime (cfg/args)            FeatureManager: discovers Feature subclasses,
  copies native XR plugin  ---env-->  installs each with its own Harmony instance
  writes UnitySubsystems manifest     PeakXR.Core sources compiled in (pure logic, unit tested)
```

Shared contracts (written first, other features code against them):

| Type | Purpose |
|---|---|
| `VRSession` | requested runtime and whether XR is rendering; `Started`/`Stopped` events |
| `VRRig` | tracking-space root, head camera, grip and aim transforms per hand. Its own root object, never under `MainCamera` |
| `VRInput` | raw per-frame controller and HMD state (`HandState`) |
| `AvatarPose` / `AvatarPoseDriver` | tracked pose for any character, applied through the game's arm IK. Local VR and remote peers use the same driver |
| `Plugin.Settings` | BepInEx `ConfigFile`. Features bind their own entries; the VR settings tab renders every entry automatically |

## UI placement in VR

No game UI stays fixed to the screen or the head in VR. Each element has a 3D anchor: the body (wrist, belt), a hand, the held item or a controller, the target object, a world sign, or another player. The only head-attached exception is perception effects, which stay a soft glow at the edge of the view. The body follow panel remains only for `HudMode = Body`, as the fallback for a HUD part a feature could not move, and for unknown overlay canvases (`CanvasKind.Info`), each logged at startup as `[ui.world] canvas '<name>' ... -> Info`.

UI at the player's own hands, wrists and held items (wheels, wrist display, item prompts, hold and fuel rings, the recenter hold ring just above the controller whose Menu is held, friend feed, refusal cues, belt slots) draws without the depth test, so the player's own hand, forearm and held item never cover or cut it, and sorts at `DrawOrder.HandUi`: after smoke, under the keyboard and every comfort overlay (fade, edge glow, vignette). Showing through a wall the hand is pressed against is the accepted cost for small hand UI. uGUI parts take `OnTop` (a material modifier with cached copies, destroyed when VR stops) or `SpatialBox`'s on-top copies; mesh cues use `UIMaterials.Create(drawOnTop: true)`. Large hand-held panels (the passport, guide book) stay depth tested like the objects they are.

## Hands and items

- Hands are independent. Each arm follows only its own controller, and any one-handed item works in either hand while the other hand stays free to climb, interact or point.
- One held item at a time, like vanilla. The free hand can grip the held item's second grip but cannot pick up a second item.
- Each hold has a primary hand, the one whose grip started it (an item that arrives without a grip, from the stick, a wheel or a friend, goes to the dominant hand), and a secondary hand, the other one, whichever side each is. Use, release to drop, throw, holster, aim, prompts and haptics follow the primary. A left-primary hold is the mirror image of the game's right-hand hold, every item grip point included (Core `HoldHands.ItemLocal`). When the primary opens while the secondary still grips the item, the item passes to the secondary, which becomes the primary: no drop, a light tick on the receiving hand, and the item eases onto its new grip over 0.25 s (Core `HoldHands.HandOff`, `AvatarPoseDriver.TrackHandoff`). Modded peers see it through the pose flags; vanilla peers see the game's own right-hand hold throughout.
- Every item is classified `OneHanded`, `TwoHanded` or `OptionalTwoHand` in a data table, with a default inferred from the item's components so new items still work.
- Custom procedural grip and hold poses are authored where vanilla has none that fits (finger presets per grip type, one-hand and two-hand holds, left-hand mirroring). Vanilla clients see the default hand.
- Grip priority (`GripIntent`): the free hand joining the held item, then a pointed grip at an item taker, then grip extensions (`IGripExtension` in `src/PeakXR/Interact/GripHooks.cs`: `interact.social`, then `inventory.vr`), then grab, climb and the interact fallback. An extension may also claim the holding hand's release (holstering) ahead of throw and drop.
- The free hand joins a two-hand item, and any item the game holds in both hands (not `rightHandOnly`), at the item's off-hand grip point (`Hand_L` under a right-primary hold, its mirror under a left-primary one), or on the item's collider surface when no grab candidate and no climbable is at the hand, so a chain, rope or ledge beside the held item takes the grip instead.
- An item taker is a target that takes the interact only because of the held item: the scout statue with an amulet, a skeleton with the Book of Bones. A grip in the pointing pose whose aim ray hits one within the game's interact reach presses interact ahead of a climb or a body-slot claim. The hand's own grab candidate still takes its grab path, and the interact waits only the finger-gun window.
- Haptics: one strength slider, `Interaction.HapticStrength` (1.0, range 0 to 2), scales gameplay cues and UI ticks alike (Core `HapticScale`; an old-scale saved value is doubled once, 0.5 becoming 1). Each hand's channel plays one pulse at a time by priority (Core `HapticChannel`): alerts (refusals, danger) over feedback (contact, progress, grab, use) over ambient feel (heartbeat, wind, surface texture, shiver, warmth). `Interaction.HapticDetail = Essential` drops ambient feel altogether (`Full`, the default, keeps it). A lower-priority pulse is dropped while a higher one plays, a pattern such as the refusal triple holds the channel for its whole length, and ambient feel also waits 0.1 s after any cue.
- A release drops or throws only an item that grip closed on (Core `ReleaseArming`). An item that arrives while the grip is already closed (a hotbar or wheel select, a friend's hand-over, a game equip) needs a fresh close first.

## Comfort defaults

Snap turn 30° (smooth turn, when chosen, at 60°/s), vignette on (medium) from any artificial motion (starting at 0.2 m/s, full at 2.5 m/s), the move stick at full speed at once with no acceleration ramp, the detached chase view eased and capped (still in Comfortable), physical crouch at a fifth of standing height, release to drop on, haptic strength 1.0 (0 to 2), head-relative movement, no head bob, no shake, sprint without FOV change, fade when the game takes the camera (ragdoll, pass out, cutscene, spectate), seated mode off (in seated mode a hand below the hips reaches down at twice the real drop, `Comfort.SeatedReachGain`, Core `SeatedReach`, applied where tracked hands become the rig's), a vignette pulse as a tumble starts, text at the 1.3° floor (`UI.TextScale` 1 to 2 grows it, Core `ReadableText.Scaled`), height auto-calibrated on first frame with recenter on a long press of the menu button.
